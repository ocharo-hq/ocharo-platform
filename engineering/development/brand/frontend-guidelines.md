# ventures.ocharo-brand — Frontend Development Guidelines

*Last updated: 2026-10-21*

Defer to `wow-two-ws/conventions/development/frontend/`.

## Workspace

- Frontend root: `engineering/codebase/ocharo-brand.frontend-services/`.
- Product app: private `@ocharobrand/web` under `apps/web/`, on `@wow-two-beta/fe 0.0.31`.
- Runtime: Node `24.11.0` from `.nvmrc`; package manager: `pnpm@10.33.2`.
- Shared packages use `packages/*` only when there is shared code; no runtime federation is configured.
- App source uses `bootstrap`, `presentation`, `application`, `domain`, and `integration` layers.
- The greeting endpoint returns plain `{ message }`; the SDK client uses `rawEnvelope` and validates that wire shape.

## Frame

- `src/bootstrap/AppLayout.vue` is the Ocharo suite frame, mounted through the layout route in `BrandRouter.ts`; every
  place renders inside it. Route metadata carries the English `label` and the sidebar `section`.
- Sections live in `src/domain/shared/BrandSections.ts`; the sidebar (`presentation/frame/BrandNav.vue`) and the phone
  bar (`PhoneNav.vue`) both read them. Adding a place means a route with `place(label, section)` and, for a new
  section, an entry there plus its icon in `ShellIcons.ts`.
- App links come from `src/application/shared/UseOcharoApps.ts`: `GET /api/runtime-config`, then build-time
  `VITE_OCHARO_{DESK,CATALOGUE,STUDIO,MARKETING,EDITORIAL,BRAND,ATLAS,WEAR,BLOG}_URL`, then the local-run defaults. The
  keys and app list match Desk's and Catalogue's. `VITE_OCHARO_BLOG_URL` now names the public blog; the blog studio is
  `VITE_OCHARO_EDITORIAL_URL`.
- Colour mode: the SDK `ColorModeProvider` and the `/theme.js` pre-paint script generated by `vite.config.ts`, both on
  `ocharo.brand.theme`. Interface colours come only from the SDK `ocharo` theme; logo proof surfaces use the fixed
  `artwork-*` tokens in `index.css`, which no dark rule redefines. The frame glass is the theme's too: the SDK
  `variant="glass"` (top bar, sidebar), `variant="glass-menu"` (menus, sheets) and `surface-glass!` (phone bar: the
  SDK `BottomNavMenu` paints `bg-background` and takes no glass variant yet).
- Frame copy is translated through `t()` and `src/domain/shared/BrandFrameUiMessages.ts` (English keys, uz/ru entries;
  an `en` entry only where the key is not the English phrase, as for `Apps menu: Editorial`).
  The interface stays Uzbek and the account menu offers no language rows: page copy is still Uzbek literals. Localizing
  the pages (Overview, Identity, Logos, Appearances, Connect, their skeletons, store notices, API failure copy, slot
  labels and dates) comes before adopting the shared `ocharo.operator.locale`.

## Commands

Run from the frontend root:

```sh
nvm use
pnpm install --frozen-lockfile
pnpm dev
```

The Vite app uses HTTPS on `8288` and proxies `/api` to the backend HTTPS profile on `8286`.
Development and browser checks use trusted HTTPS; configure `VITE_API_CA_PATH` for the backend certificate.
`VITE_API_TARGET` can select a running local backend for those checks; the default is `https://localhost:8286`.
Browser checks run the API against a throwaway content root (`--contentRoot <scratch>`), never the ignored `App_Data/`.

```sh
pnpm typecheck
pnpm test
pnpm format:check
pnpm lint
pnpm build
```

Typecheck includes the Vue SFC compiler. Tests cover the frame (landmarks, apps menu, sections, breadcrumb, rail,
phone bar), the account menu with and without an Ocharo session and the Desk name and email, the app-link config seam,
the first paint, frame
translations, brand read states, the session client, the brand API client and architecture imports.
`tests/helpers/BrandApp.ts` mounts the whole app through the real route table.

## Delivery

`pnpm build` produces `apps/web/dist/` with `theme.js`. `pnpm deploy` rebuilds and replaces the generated API `wwwroot/`
artifact. Run `deploy` only when replacing that generated frontend is intended.
Docker installs from the workspace lockfile and copies the same `apps/web/dist/` artifact into the .NET image.
API calls remain same-origin in development and production.
