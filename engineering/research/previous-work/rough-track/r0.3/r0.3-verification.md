## Persistence and access evidence

The `design-documents` API validates bounded JSON snapshots, explicitly checks current organization membership,
uses the existing session/antiforgery policy, and enforces `expectedRevision`. Revisions are immutable;
archival increments revision and prevents further saves. New persistence uses migration004 and PostgreSQL JSON.

Executed tests cover owner/editor/viewer access, foreign organizations, malformed/oversized/deep snapshots,
duplicate JSON keys, Unicode/null handling, stale and concurrent writes, immutable history and archive rules.
Runtime checks saved both document kinds with substantial Unicode payloads, rejected foreign reads with 404,
rejected stale writes with 409 and verified the first historical revision remained unchanged. Snapshot hashes
and authenticated access survived API restart. A subsequent full PostgreSQL/API stop and owned cold start
preserved both saved catalogue documents, both cards, card revision 3 and the edited contact location.
[Full restart evidence](review/restart-result.json) also confirms the authenticated browser session survived. Runtime evidence is retained locally in
`.local/verification/design-document-state.json` without exporting credentials.

Browser flows created two catalogue documents and two card documents in the local Ocharo review organization.
The catalogue review saved a 149000 UZS edit, garment reordering, movement, resizing and crop changes; reopening
restored them. The card review saved contact and palette edits through revision 3. Saving is explicit, and a failed
or conflicting save keeps the current working document. Import validation fails without replacing that document.

A simulated media-list 503 after a successful image upload left the editor mounted and preserved an unsaved 181000
price edit. This verifies that background refresh errors cannot silently discard the active design.
Evidence: [upload recovery](review/upload-recovery-result.json).

## Remaining boundaries

- Developer review of overall design, density, template fidelity and preferred overview remains open.
- UI controls are English; template copy supports Uzbek/Russian/English.
- PDF output is an RGB trim proof with rasterized text, no bleed, no press ICC profile and no selectable text.
- System Georgia/Arial rendering follows HTML geometry; historical printed PDF baselines/gradients are not pixel-identical.
- Garment reordering is within existing page slots; page order is fully editable. Blank composition and arbitrary
  garment transfers between category pages are later work.
- Uploaded photos use existing PNG/JPEG validation and 5MB limits. Imported JSON references must resolve in the
  authorized workspace; it is not an asset-embedded portable archive.
- API history/archive is implemented; this editor exposes save, copy and reopen rather than a full history browser.
- Existing snapshot size/node limits bound document growth; excessive duplication can fail save while retaining edits.
- Marketing, scheduling, provider publishing, journal integration and the business MCP adapter are not implemented here.
- No new GitHub organization, remote transfer, release, deployment, commit or push occurred. The relocated native
  permission record requires repair before the requested auto-commit can run.
