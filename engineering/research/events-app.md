# Ocharo Events app

*Last updated: 2026-11-10*

Ocharo's Events service: the first service out of Desk (`ocharo-ws` [app boundaries](../../../../docs/app-boundaries.md#services),
WoW2 `events-integration #61`). Its one job is tracking trade events; WoW2 Events owns the catalog and the tracking
rows, and this service is their Ocharo face. Design picks by the platform lane, 2026-11-10; the build is recorded in
v0.3 Iteration 8.

- ✅ R2: Desk's Events page, routes and exchange left at `v0.3.12`; every app's menu lists Events (marketing `v0.1.18`,

## #1 Shape

- One service inside `ocharo-platform`, built like Brand: `engineering/codebase/ocharo-events.backend-services/`
  (`OcharoEvents.{Api,Application,Domain,Infrastructure,Persistence}`, unit and E2E tests) and
  `ocharo-events.frontend-services/` (pnpm workspace, app `apps/web`), one image serving the API and the SPA.
- It shares no code with Desk or the other services. Desk's Events slice moves here: the controller, queries and
  commands, `EventsServiceRepository`, `EventsServiceMapper`, `EventValidationService`, the models, and the frontend's
  `presentation/events`, `application/events`, `domain/events`, `integration/events` and their messages and tests.

## #2 Data

- No event tables: WoW2 Events holds the catalog and the organization's tracking (E1).
- Schema `ocharo_events` holds only the Data Protection key ring; sessions live in the be sdk's PostgreSQL cache, schema
  `ocharo_events_cache`. A restart or a deploy keeps everyone signed in, as in Brand and Catalogue.

## #3 Contract

- The API keeps Desk's routes and wire unchanged, so the page moves without a rewrite:
  `GET|POST /api/organizations/{organizationId}/events`, `GET .../events/summary`,
  `GET|PUT|DELETE .../events/{eventId}`; fact edits and deletes keep answering 410 Gone.
- Plus the suite's own: `/api/identity/*` (BFF), `/api/runtime-config`, `/api/system/status`, `/health`.

## #4 Access

- A BFF session from Ocharo's Identity. A route's organization must be the session's organization, and the person
  must hold `events:read` in it; anything else answers 404, as Desk's filter does.
- Every call to WoW2 Events exchanges the person's token for resource `events` (`events.read`, `events.track`); Events
  checks the scope and the `events:*` permission against the token's organization. Proposing a new event and saving
  tracking need `events.track`; nothing here needs `events.import`, `review` or `admin`.

## #5 Identity registration

- Client 11, `ocharo-events`, display name "Ocharo Events", permission namespace `events`.
- Grants `authorization_code` and `token_exchange`; exchange resource `events`; scopes `events.read`, `events.track`.
- Secret generated by Wheelhouse. Redirect, sign-out and signal URIs typed per environment from the new site's URL:
  `{Url}api/identity/callback`, `{Url}`, `{Url}api/identity/signal`.
- Roles keep their `events:*` permissions from v0.3 Iteration 2: owner and admin all four, editor read and track,
  viewer read.

## #6 Deploy

- Service `events` and site `events` in `deployment/deploy.yml`; image `deployment/events/Dockerfile`; a `migrate`
  item and a `configCheck` item like Brand's.
- Settings: `Identity:Client:*` linked from client 11; `Events:BaseUrl` linked from resource 3's Uri, as Desk's is;
  `Events:Catalog` default `ocharo-fashion`; the `OcharoApps:*` menu keys like Brand's.

## #7 Frame

- The page renders through `AppFrame` like every Ocharo app, `current-app="events"`, with no sidebar while it has one
  place; `/` opens the session's organization's events.
- The suite's menu gains `events` in every app at once (`OcharoApps:Events`, `OCHARO_EVENTS_URL`), in R2.
