# Planning rules

*Last updated: 2026-09-26*

Use the [shared planning conventions](../../../../../conventions/planning/planning-conventions.md).
Current work belongs in one active track; future work belongs in the ordered backlog.

Preserve the requested first-commit checkpoint. A successful starter build proves scaffolding,
not tenant isolation, provider access, or the content workflow. Record actual verification separately.

The bootstrap is a coordinated whole-tree task. Open subject vectors when independent product
subsystems begin; do not create speculative empty lanes for every future capability.
