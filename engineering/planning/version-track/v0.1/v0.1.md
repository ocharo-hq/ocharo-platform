### Iteration 5 — Named catalogues and product review

Implementation is present; the following owner-review scenarios remain unverified.
See [catalogue architecture](../../../architecture/catalogue-outputs.md) for the current contracts.
Automated gates and the canonical IDE entry are in the [review verification](../../../research/catalogue/2026-10-01-catalogue-review/verification.md).

- [ ] Open the retained pilot’s Desk link → canonical gallery opens without losing pilot edits
- [ ] Create, rename, duplicate, activate and archive a catalogue → saved history remains available
- [ ] Choose one content language → interface language stays independent
- [ ] Create web-only, PDF-only and combined catalogues → each opens the matching designer
- [ ] Edit ordered web/PDF pages → changes and activation stay independent between outputs
- [ ] Change web theme, copy, media group and price flags → preview matches the released reader
- [ ] Confirm one product language → its unresolved-copy indicator clears without confirming others
- [ ] Leave an open review question → the product remains excluded from public catalogue output
- [ ] Edit 1–9 and 10+ prices → UZS values persist and price confirmation resets
- [ ] Load legacy pricing unchanged → original values remain intact until an explicit price edit
- [ ] Deactivate a page → preparation and public output omit it
- [ ] Mix confirmed/unconfirmed products → web retains confirmed siblings; PDF excludes that whole page
- [ ] Prepare a named edition → explicit publication keeps prior released downloads immutable
- [ ] Revoke product approval after preparation → stale PDF is withheld; safe web content remains
- [ ] Publish a second named catalogue in the same language → the first remains independently available

No live publication or completed human review is implied by automated test results.
