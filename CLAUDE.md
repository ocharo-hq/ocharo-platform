# ventures.brand-workspace

*Last updated: 2026-09-26*

General brand-operations product, beginning with Content & Publishing and Ocharo as its first organization.

## Instructions

- Shared wow-two conventions apply; `.claude/rules/file-references.md` is a lazy document lookup.
- Current state lives in `product/context.md`; execution lives in `engineering/planning/`.
- The developer owns the first commit; full scaffolding follows it.
- Native commit permission is authoritative. Missing state means OFF; never write permission state manually.
- Use .NET 10 and Vue 3, strict TypeScript, Vite, Tailwind v4, and the public Vue SDK exports.
- Treat the template's React frontend and classic solution format as adaptation inputs, not current standards.
- Keep code under `engineering/codebase/brand-workspace.{backend,frontend}-services/`.
- Keep shared infrastructure and reusable brand capabilities suitable for wow-two libraries.
- Keep garment semantics optional and Ocharo facts in tenant configuration.
- Preserve source records and real media in Maftuna's workspace; import through explicit provenance contracts.
- Keep Studio independently usable; never adopt its browser workspace UUID as SaaS authorization.
- Live provider authorization and publication need their own explicit account/content scope.
- Read the template audit before scaffolding into this already established repository.
